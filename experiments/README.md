# Measurement campaign (thesis Ch. 6)

Automated collection and analysis of the three variables operationalized
in the thesis proposal — systemic latency ($L_s$), E-STOP determinism,
and positional error ($E_p$) — plus latency decomposition, inter-run
dispersion, event-delivery completeness, and backend resource footprint.

Everything is measured inside ONE rosbag2 clock domain via the
`/webapp_ros/markers` topic the backend publishes (see
`rust_app/src/metrics.rs`): each metric is a subtraction between
messages of the same bag, never a comparison across clocks.

The campaign comprises 12 platform–scenario combinations × 30 runs =
**360 runs**: scenarios S1–S5 on Turtlesim and on the TurtleBot3 Waffle
(Gazebo), and S6–S7 on the 2-DOF manipulator ([`../simulation`](../simulation)).

## Pipeline

```
runner.py ──► data/<platform>/<scenario>/run_NNN/   (rosbag2 + metadata.json)
                │
analyze.py ─────┴──► results/<platform>/<scenario>/  (summary.csv, aggregate.json, figures)
                        │
export_pgfplots.py ─────┴──► <out>/*.dat             (data read by the thesis plots)
stats_extra.py  ──► medians/IQR, Spearman, 95% CIs  (printed; reported in Sec. 6.8)
```

The chain is reproducible end to end: re-running `analyze.py` on the 360
bags yields `summary.csv`/`aggregate.json` files identical to the ones in
`results/`, and `export_pgfplots.py` then yields the 18 `.dat` files used
by the thesis figures byte for byte.

## Layout

| File | Role |
|---|---|
| `scenarios.py` | Program payloads + per-platform recording/reset config (S1–S5 mobile ×2 platforms, S6–S7 arm) |
| `runner.py` | Campaign runner: reset → `ros2 bag record` → `POST /api/execute` (+ timed abort) → archive with metadata. Retries any run whose bag missed the start marker |
| `analyze.py` | Bags → per-run metrics → `summary.csv` + `aggregate.json` (μ/σ/min/max) + figures |
| `export_pgfplots.py` | Bags + `summary.csv` → `.dat` files for the thesis pgfplots figures (medians and IQR for latency) |
| `stats_extra.py` | Robust and inferential statistics: median/IQR, Spearman (sequence length vs $L_s$), 95% CIs |
| `diagnose.py` | Integrity check of every bag (start marker, step markers vs expected, finish/abort) |
| `rerun_gazebo.sh` | Unattended re-run of the Gazebo campaigns with the hardened runner |
| `requirements.txt` | Pinned Python dependencies used to process the campaign |

## Data

| Path | In git | Contents |
|---|---|---|
| `results/*/*/summary.csv` | yes | One row per run with every metric (basis of thesis Annex B) |
| `results/*/*/aggregate.json` | yes | μ, σ, min, max and n per metric |
| `data/http_rtt_ms.json` | yes | 100 samples of the browser→backend round trip (2.47 ± 0.17 ms, Sec. 6.4) |
| `data/<platform>/…` | no | The 360 raw rosbag2 bags (~200 MB), published separately as a release asset; extract them into `data/` to re-run the analysis |
| `results/**/*.png`, `pgfplots/` | no | Figures and `.dat` files — regenerated by the scripts |

## Setup

```bash
source /opt/ros/jazzy/setup.bash          # rosbag2_py and message packages
python3 -m venv --system-site-packages .venv
./.venv/bin/pip install -r requirements.txt
```

## Running a campaign

```bash
# 1. Start the platform under test:
#    turtlesim:  ros2 run turtlesim turtlesim_node
#    waffle:     export TURTLEBOT3_MODEL=waffle && ros2 launch turtlebot3_gazebo empty_world.launch.py
#    arm:        ros2 launch twobot_gazebo start_world.launch.py   (see ../simulation)
# 2. Start the backend:  cd rust_app && cargo run

python3 runner.py --list                          # available scenarios
python3 runner.py S3_square --platform turtlesim -n 30
python3 runner.py --rtt 100                       # browser-hop RTT estimate
```

Runs are resumable: existing `run_NNN/metadata.json` are skipped.

## Analysis

```bash
./.venv/bin/python diagnose.py                            # bag integrity
./.venv/bin/python analyze.py data/ --results results/    # metrics + figures
./.venv/bin/python stats_extra.py                         # medians, Spearman, CIs
./.venv/bin/python export_pgfplots.py --out pgfplots/     # thesis plot data
```

## Initial-conditions protocol (why runs are comparable)

- **turtlesim**: `/reset` service before every run (bounded canvas).
- **waffle**: empty world; every metric is computed relative to the pose
  at the run's own start (segmented by markers), so absolute drift
  between runs is irrelevant.
- **arm**: homing motion (`[0, 0]`) through the platform API before
  every run — joint space is absolute.

## Outputs per scenario

- `summary.csv` — one row per run (all metrics).
- `aggregate.json` — μ, σ, min, max, n per metric + marker completeness rate.
- Figures (one representative run + aggregates, deliberately not 30×):
  `trajectory_xy` (real vs ideal), `timeseries`, `joints_timeseries`,
  `estop_timeline`, `latency_hist`, `estop_hist`, and `spaghetti_xy`
  (all-runs overlay — the repeatability figure, S3 only).
